# Pilot run review

## Pilot flow

- Scored course completion opens the review automatically and reveals a hidden HUD.
- **COURSE → END PRACTICE & REVIEW** ends an unfinished course or free exploration recording. It does not mark the course complete or award a score.
- **VIEW LAST RUN REVIEW** reopens the latest review during the current session. Restart to begin a new recording. Review does not change thruster commands, pause physics, disconnect, or disarm SITL.
- Course restart/map reset clears the active recorder while leaving the last review available.

## Metrics and sources

`RovTrainingCourse` feeds `RovRunRecorder` at the existing physics-step cadence, for local and external SITL physics. Timing uses simulation dt. Idle time before motion starts is excluded, using the existing 0.05 m/s or 0.05 m movement thresholds. Recordings freeze at completion or explicit practice end.

The route uses Unity vehicle positions, not ROS odometry, and is labelled accordingly. It is a top-down X/Z projection; travelled distance includes all three dimensions. Collision markers use contact points from the existing collision-entry callback and its 0.4-second debounce. No extra contacts are generated or collision rules changed.

Depth/heading RMS and score reuse the existing course metrics. These are errors relative to the currently active gate/hover/dock target, including transitions. Free-swim and RoboSub exploration maps have no target errors or score.

Each thruster reports simulation-time-weighted mean absolute output, peak absolute output, and direction reversals across ±5% output. A neutral interval does not clear the last significant direction. Outputs include thruster health derating and are force fractions, not power, RPM or real measured thrust. Low-speed thrust time counts at least one horizontal output of 10% or more while 3D speed is below 0.15 m/s. It is a station-keeping effort proxy, not a claim that a correction was unnecessary.

## Comparison and persistence

Only an exact existing scenario key (including map, start, conditions and control mode) is compared. Completed courses compare with completed courses; ended practice compares with ended practice. Practice duration/progress may differ. Changing conditions/control mode during movement invalidates comparison and persistence for that run. Both local and SITL control modes retain the existing qualification rules.

Optional feedback summaries extend `RovRunResult` in the existing version-1 `training-runs.json`, using the existing atomic write/backup path. Completed-run history remains capped at 100 and best-score history at 256. Ended-practice summaries occupy a separate 20-entry list and never enter best scores. Feedback version 0 indicates legacy history without thrust metrics; it remains eligible for time/collision/score comparison without inventing historical thrust data. Recording disabled by tests (`RecordResults=false`) prevents all history writes.

Full routes/contact points remain in memory for the latest review and are not written to history. Routes are sampled initially at 5 Hz in simulation time, bounded to 512 points and progressively decimated across the whole trace for longer runs. Start and final positions remain available. Up to 128 contact markers are retained; the full collision count still appears in the review. There is no per-physics-step allocation, route I/O or UI update.

## Validation

`ClubROV.Simulation.Editor.RovRunReviewChecks.Run()` uses an isolated temporary vehicle/course and never resets the user's live vehicle. It checks weighted thrust/time, reversal counting, distance/endpoints, finite-input rejection, snapshot/reset isolation, long-run bounds, legacy and extended JSON, matching comparisons, separate practice persistence, existing 1 MB history-size cap, automatic completion, frozen recording, free-swim collision debounce, reset, changed conditions, UI lifecycle, and unchanged user history.

Visual QA uses an explicitly labelled synthetic sample generated by `Preview()`; it never appends a saved run. The real Game-view screen was inspected for route markers, metric readability, comparison text, bars, scrolling and close-button placement. No full manually piloted course or SITL mission was executed for this change.
