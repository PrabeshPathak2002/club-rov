# ClubROVSim context

Windows desktop ROV training prototype in the existing club-rov repository. Editor 6000.6.7f1, Universal 3D template, URP 17.6.0, Input System 1.20.1. Unity Pipeline 0.9.1-exp.1 was approved for local Editor automation. No second MCP provider is needed.

Baseline: the fresh Editor compiled with zero Console errors and warnings. SampleScene is the untouched template scene. The new PoolTraining scene is generated through the Editor by Assets/ROV/Editor/PoolSceneBuilder.cs. Runtime components live in Assets/ROV/Scripts and UI in Assets/ROV/UI. No networking, ROS, ArduSub SITL or real-hardware connection is implemented.

Use Unity units as metres, +Z forward, +X starboard, +Y up. Source STL uses millimetres with +X forward/+Y port/+Z up; the importer converts and centers it. The September viewing mesh is a visual reference, not calibrated mass/collision geometry. The six thrust-axis lines now come from the live Fusion snapshot; hydrodynamic coefficients and mass/balance remain provisional.

Apply forces only in FixedUpdate. Separate input from physics so a future SITL bridge can supply six actuator commands. Use UI Toolkit, not OnGUI. No tests framework has been added. Meaningful mixer checks are available via the scene builder; runtime checks must also establish actual movement and reset behavior.

The live Future ROV assembly was measured on 23 October 2026; Docs/FUSION_GEOMETRY.md and Docs/fusion-geometry.json contain its envelope and six analytic thrust-axis lines. These now drive the runtime layout and collider. Horizontal allocation uses a cached minimum-norm sway/surge/yaw matrix from the measured lever arms; scaling all channels together preserves force balance. The reference point is geometric, not measured COM. All printed parts use Bambu Lab PETG Basic at 100% infill (corrected from an initial 10% statement). Do not estimate their mass by applying a 10% solid-volume multiplier.

Pilot tuning defaults: raw-stick dead zone 0.15, translation sensitivity 0.65, yaw sensitivity 0.5, mixed-force limit 0.6. Dead zones are applied once to raw stick data. RovControlChecks uses temporary synthetic devices and restores the original devices, camera, vehicle and input state. Six mixer, eleven motion/lifecycle and twelve synthetic control checks passed. A physical Xbox Controller is detected, and all controls were confirmed working in a hands-on test.

Keep Library, Temp, Logs, UserSettings, generated IDE projects and player builds out of Git. Include Unity-generated .meta files with assets. Do not change firmware or upload simulator assets without a reviewed source set.

FPV revision: PC_Renderer contains RovFpvRendererFeature, installed through Editor APIs. The pass runs after post-processing before UI, uses a persistent imported RTHandle for a 640x480/30 fps held video frame and swaps cameraColor to a letterboxed display output. It explicitly requires an intermediate color target; _BlitTexture is bound through RenderGraphUtils.BlitMaterialParameters. No obsolete Blit/OnRenderImage hooks or hand-written scene YAML. The pass is gated to the Game camera with an active RovFpvCameraFeed, frees history on chase/disable and destroys its material on disposal. It supports the single ROV camera used in this scene. The HUD is not sampled into the feed. Standard Pi Camera 2 lens baseline is 48.8 degrees vertical; noise/codec effects are artistic. Ten bounded FPV checks cover cadence, shader compilation, resource lifecycle and lens restoration; twelve input/camera and nineteen course/UI checks also passed with the effect installed.

Training revision: pool interior 20 x 24 x 3.5 m; three numbered +Z gate crossings, cyan 3 s hover hold and green 3 s docking hold. RovTrainingCourse on the rigid body subscribes to the vehicle reset event, counts collision entries and resets tracking from Rigidbody.position to avoid interpolation lag. HUD controls are mouse-operated/non-focusable to preserve pilot gamepad bindings. RovWaterVisibility uses the URP beginCameraRendering event and restores RenderSettings on disable; 1–20 m artistic contrast visibility, default 8 m. Nineteen course/UI/visibility checks supplement the eleven physics and twelve input checks. No full physically piloted course-completion run has been recorded.
