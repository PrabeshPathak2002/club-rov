# ClubROVSim context

Windows desktop ROV training prototype in the existing club-rov repository. Editor 6000.6.7f1, Universal 3D template, URP 17.6.0, Input System 1.20.1. Unity Pipeline 0.9.1-exp.1 is included for local Editor automation; its CLI is a separate machine dependency. Reuse this provider rather than installing a duplicate bridge.

Initial validation baseline: the fresh Editor compiled with zero Console errors and warnings. SampleScene is the untouched template scene. PoolTraining is included in the repository and can be generated through the Editor by Assets/ROV/Editor/PoolSceneBuilder.cs. Runtime components live in Assets/ROV/Scripts and UI in Assets/ROV/UI. ArduSub SITL networking is implemented as described below; ROS and real-hardware connections are not implemented.

Use Unity units as metres, +Z forward, +X starboard, +Y up. Source STL uses millimetres with +X forward/+Y port/+Z up; the importer converts and centers it. The September viewing mesh is a visual reference, not calibrated mass/collision geometry. The six thrust-axis lines now come from the live Fusion snapshot; hydrodynamic coefficients and mass/balance remain provisional.

Apply local-mode forces in FixedUpdate. SITL mode exclusively owns Physics.simulationMode=Script and calls RovDynamics.ApplyForces once before each Physics.Simulate step. Never apply both paths together. Use UI Toolkit, not OnGUI. No tests framework has been added. Meaningful mixer checks are available via the scene builder; runtime checks must also establish actual movement and reset behavior.
