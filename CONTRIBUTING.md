# Contributing

Start with the [new member guide](Documentation/NEW_MEMBERS.md). Choose a small task from the [roadmap](Documentation/ROADMAP.md), agree on an expected result with a project mentor, and work in a separate branch.

A pull request should explain the problem, the change, how it was checked, and what remains uncertain. Update relevant documentation and BOM entries. Request review from someone familiar with the subsystem before merging.

Use explicit units, exact part/firmware revisions where known, and TBD where unknown. Distinguish planned, implemented, bench-tested, and water-tested behavior. Link original sources and explain important tradeoffs. Record failed tests as well as successes.

Do not commit credentials, machine-specific configuration, personal paths, or raw session logs. Confirm redistribution rights before adding third-party assets. The initial ignore rules exclude firmware and CAD binaries; extend them deliberately as reviewed deliverables are added.
